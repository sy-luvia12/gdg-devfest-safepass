# PR 준비 초안

이 문서는 팀 검토용 초안이다. 아직 커밋·push·PR 생성·merge·배포는 하지 않았다.

## PR 제목

```text
feat: 학적 명단 기반 재학생 자동 인증 구현
```

## PR 본문

기존에는 학생이 본인 사진과 학생증을 제출한 뒤 학생회의 수동 승인을 기다려야 했습니다. 이제 학교·학번·이름·학교 이메일이 학적 명단의 같은 행과 일치하면 즉시 승인하고, 불일치하면 수정 후 다시 시도할 수 있도록 안내합니다. 기존 온보딩 화면과 사진 등록은 유지했습니다.

### 주요 변경

- 기존 데모 학생 정보와 일치하는 가상 JSON 명단 및 mock 자동 인증 구현
- 인증 성공·실패 안내와 성공 후 축제 이동 추가, 이전 승인 대기 경로 정리
- Firebase에서 실제 서버 인증 상태를 읽고, 신규 입장권 발급 전 승인 여부 확인
- 서버 전용 Google Sheets 조회 준비: 검증된 로그인 이메일과 학교 도메인 사용, 읽기 전용 접근, 전체 명단·자격 증명 비공개
- 이미 승인된 사용자와 스태프 흐름 유지
- 설정·테스트·제약 사항을 한국어로 문서화: [재학생 자동 인증](student-verification.md)

### 검증

- 기존 백엔드 단위 테스트 48개 통과
- 신규 인증 테스트 19개 통과: 정상 일치, 불일치, 잘못된 정보, 재시도, 기존 승인, 입장권 발급, 스태프 검표, 서버 오류 등
- 웹 및 Functions TypeScript 빌드 통과
- 웹 lint 통과, 기존 React 경고 존재
- 사용자 로컬 동작 확인 완료
- Firebase CLI·JDK 미설치로 에뮬레이터 통합 테스트 미완료
- 실제 Google Sheets 연결과 배포 환경 테스트 미완료

### 리뷰 및 배포 전 협의

실제 Google Sheet는 아직 생성·연결하지 않았습니다. 현재 로컬 데모는 가상 JSON 명단을 사용하며, Firebase 모드에는 Sheets API 활성화, 서비스 계정 뷰어 공유, 서버 환경 변수 설정이 필요합니다.

특히 백엔드 담당자에게 다음 항목 검토를 부탁드립니다.

- 기존 Firebase 사용자 중 인증 상태가 없는 사용자의 온보딩·마이그레이션 정책
- 사진의 임시 Firestore 저장 방식, Storage·서명 URL 전환과 개인정보 삭제 작업
- 기존 행사별 명단 화면과 학교별 학적 명단의 관계
- 취소표 대기자 재배정 시 수신자 인증 확인

블록체인 계약과 Firebase 권한 규칙은 변경하지 않았습니다. 이 PR은 자동 인증 구현과 Sheets 연결 준비를 공유하기 위한 것이며, 실제 서비스 배포 승인을 의미하지 않습니다.

## 이후 Git 공유 절차

1. `feature/onboarding-manwoo`에서 변경 파일과 diff를 확인한다.
2. 이번 기능에 해당하는 코드·가상 명단·테스트·문서·의존성 파일만 선택해 커밋한다. `.env`, 서비스 계정 키, 실제 학생 명단은 포함하지 않는다.
3. 별도 승인 후 `origin`의 같은 이름 브랜치로 push한다. push는 해당 브랜치를 공유하는 단계이며, 코드 병합은 별도다.
4. GitHub에서 `feature/onboarding-manwoo`를 비교 브랜치로, **팀이 지정한 통합 브랜치**를 대상 브랜치로 선택해 우선 Draft PR을 만든다. 이 문서의 제목·본문을 사용한다.
5. 프론트·백엔드 담당자의 리뷰와 필요한 통합 테스트를 거친 뒤 팀 정책에 따라 병합한다. 실제 Sheets 설정과 배포는 별도로 승인·진행한다.

이 저장소의 CI·배포 설정에 따라 push나 PR이 자동 작업을 실행할 수 있으므로, 공유 전에 팀의 설정을 확인한다.
